# Mira Mobile 夜间接力放行规则

状态：临时授权

生效时间：2026-08-29

失效时间：2026-08-29 12:00（Asia/Shanghai）

唯一状态台账：`docs/work-ledger.md`

> 本文件不是第二套台账，只定义 2026-08-29 夜间至中午前的施工放行规则。任务状态、依赖、验收结果仍统一回写 `docs/work-ledger.md`。

## 1. 临时决策授权

在本授权有效期内，Mira 可以作为当前 Mobile 施工链路的放行决策者，判断一张任务卡是否已经具备继续后续施工的充分证据。

当实现合同、代码基线和自动化证据已经足以支撑后续任务时，可以将该卡标记为：

**有条件通过（放行后续）**

该状态代表：

- 当前实现已经达到可供后续任务可靠依赖的程度；
- 仍存在待用户补配置、真机或人工验收的尾项；
- 这些尾项必须继续记录，不能被“有条件通过”抹掉；
- 对后续依赖判断而言，视为前置实现依赖已经满足。

“有条件通过”不等于“最终完成”。最终完成仍需补齐对应验收证据。

## 2. 可以直接有条件通过的情况

满足以下条件时，Mira 可以直接宣告有条件通过并放行后续任务：

1. 任务要求的实现已经进入目标仓库的合法基线，或共享合同已经冻结并有代码 / 测试证据；
2. 与后续施工相关的类型、接口、schema、状态语义和数据边界已经可验证；
3. 当前可执行的 typecheck / lint / test / build / CI 已通过，或剩余失败能够明确归因为外部环境而非实现语义错误；
4. 剩余未完成项不会合理地推翻后续任务所依赖的接口或产品事实；
5. 剩余风险、人工验收项和缺失环境已经明确写回台账或 PR。

## 3. 默认不阻塞夜间施工的人工事项

以下事项默认作为“待用户验收 / 待补配置”挂账，不单独阻塞后续任务：

- Cloudflare API Key、Worker Secret、Provider Key 等由用户持有的 Secret 注入；
- GitHub PAT / GitHub App 凭据等外部授权；
- Cloudflare 账号级资源绑定、正式部署权限或控制台确认；
- Android / iOS 真机人工交互验收；
- 40 分钟真实录音 smoke；
- 签名构建、真实账号登录、跨端人工联调；
- 其它只能由用户本人完成但不改变已冻结实现合同的验收项。

施工方不得伪造这些证据，也不得把 Secret 写入仓库。正确处理方式是：

```text
完成可施工实现
-> 用本地 / mock / contract / 自动化证据证明实现边界
-> 标记“有条件通过（放行后续）”
-> 把人工事项记录为待验收
-> 继续后续任务
```

## 4. 真正会阻塞的情况

只有以下情况可以阻塞对应施工链：

- 无法确定权威接口、稳定 ID、schema 或状态语义，继续施工会依赖猜测；
- 自动化或代码证据已经表明共享合同存在真实错误；
- 后续任务必须依赖一个尚不存在或未冻结的 API / 数据合同；
- 需要改变 `docs/shiyan/` canonical truth、Desktop / Host 业务语义或其它跨仓库正式合同；
- 存在不可逆数据破坏、Secret 泄露、安全越权或发布级高风险；
- 继续施工只能通过伪造远端能力、假成功或假数据成立。

即使出现真实阻塞，也只阻塞受影响的任务链。其它不受影响的卡继续推进。

## 5. 前置依赖判定

夜间接力不得只依据任务卡上的“完成 / 未完成”文字机械停机。

每次判断依赖时，应查看当前真实基线：

- 目标分支 HEAD；
- 已合并 PR；
- 共享类型 / API / schema / route；
- CI / Review / 自动化结果；
- `docs/work-ledger.md` 的最新状态和遗留验收项。

如果前置卡已经达到“有条件通过（放行后续）”，后续卡立即视为解锁，不等待用户醒来重新确认。

同一轮执行中，前置卡合入或被判定有条件通过后，应重新读取 HEAD / 台账，并尽可能继续下一张已解锁任务，不必人为等待下一次定时唤醒。

## 6. 状态写法

推荐台账状态：

- `待实施`
- `实施中`
- `有条件通过（放行后续）：<已完成证据>；待用户验收：<尾项>`
- `完成`
- `阻塞：<真实阻塞原因>`

不得使用“等待用户配置 CF Key”作为整条施工链的阻塞理由，除非没有该配置就无法定义或验证下游必须依赖的真实合同。

## 7. 到期与交接

2026-08-29 12:00（Asia/Shanghai）后，本临时放行授权自动失效。

到期前已经记录的“有条件通过”状态保留，用户醒来后统一验收未完成尾项。

交接时应汇总：

- 已完成 / 有条件通过的任务；
- 已合并 PR 与关键 commit；
- 自动化验证证据；
- 需要用户补的 Secret / 配置；
- 需要用户做的真机 / 人工验收；
- 仍存在的真实阻塞。
